## 1. 背景与目标

### 1.1 背景

做一个 B2C 综合商品购物平台，形态对标京东：多级分类浏览、商品搜索、SKU 规格选择、购物车、下单结算、订单管理，并提供后台商品与订单管理能力。首期以 MVP 为目标，覆盖完整购物闭环。

项目同时承担工程能力验证职责：核心链路必须可自动化验证，交付时附测试报告、并发结论与压测结论。

### 1.2 目标

| 维度 | 目标 | 判定方式 |
|---|---|---|
| 用户侧 | 从商品发现到下单全流程无阻断 | 端到端验收全通过 |
| 管理侧 | 可维护商品、分类、SKU 库存，可处理发货 | 管理端验收全通过 |
| 技术侧 | 前后端分离、契约清晰、SKU 模型可扩展 | 接口契约零歧义，联调无返工 |
| 质量侧 | 不超卖、不越权、不重复扣减 | 并发与安全专项全通过 |

### 1.3 范围

**做**：商品浏览与搜索、SKU 选择、购物车、下单（模拟支付）、订单查询、收货地址、超时自动取消与自动完成、后台商品与分类与订单管理、图片上传、JWT 鉴权。

**不做**（后续迭代）：真实支付网关、退款售后、优惠券与秒杀、评价体系、物流轨迹、多商家、推荐算法、消息通知、管理员操作审计、软删除。

> 边界写清楚比写清楚"做什么"更有用：验收时"这个没做"和"这个没要求"是两件事。

### 1.4 角色

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 游客 | 浏览、搜索、看详情 | 加购、下单、看订单 |
| 买家 | 全部购物流程、地址管理 | 进管理端 |
| 管理员 | 买家全部能力 + 商品/分类/订单管理、上传图片 | 无（MVP 不分运营/客服/仓储） |

## 3. 功能结构

```
玄武商城
├── 用户端
│   ├── 首页        轮播 / 一级分类入口 / 推荐 8 个商品
│   ├── 商品        列表（筛选·搜索·排序·分页）/ 详情（SKU 联动）
│   ├── 购物车      加购 / 改数量 / 删除 / 选中结算
│   ├── 结算下单    地址选择 / 金额确认 / 提交
│   ├── 我的订单    列表（状态 Tab）/ 详情（状态时间线）
│   └── 个人中心    登录注册 / 地址管理
├── 管理端
│   ├── 商品管理    列表 / 新增 / 编辑（动态 SKU）/ 上下架 / 删除
│   ├── 分类管理    三级树 / 增删改
│   ├── 订单管理    查询 / 发货
│   └── 图片上传    主图 / 图集
└── 系统任务
    ├── 30 分钟未支付 → 自动取消 + 回滚库存
    └── 发货 15 天 → 自动确认收货
```

## 4. 核心流程

### 4.1 下单主流程

```
浏览/搜索 → 商品详情 → 选规格 → 加入购物车 → 去结算
                                              │
                                     选地址、看金额
                                              │
                                          提交订单
                                              │
                     ┌────────────────────────┼────────────────────────┐
                     ▼                        ▼                        ▼
              30 分钟未支付             立即支付                 主动取消
                     │                        │                        │
                     ▼                        ▼                        ▼
              自动取消+还库存            待发货 paid            已取消+还库存
                                              │
                                          管理员发货
                                              │
                                         待收货 shipped
                                              │
                          ┌───────────────────┴───────────────────┐
                          ▼                                       ▼
                     确认收货                            15 天自动确认
                          └───────────────────┬───────────────────┘
                                              ▼
                                         已完成 completed
```

### 4.2 订单状态

| 状态 | 含义 | 谁能改 | 下一站 |
|---|---|---|---|
| `pending` | 待支付 | 买家支付/取消、系统超时 | `paid` / `cancelled` |
| `paid` | 待发货 | 管理员发货 | `shipped` |
| `shipped` | 待收货 | 买家确认、系统超时 | `completed` |
| `completed` | 已完成 | — | 终态 |
| `cancelled` | 已取消 | — | 终态 |

**规则**：只有上表这 7 条路径合法，其余组合一律拒绝且不产生任何副作用（不改状态、不动库存）。

## 5. 页面规格

> 每页写清四件事：**要什么元素、空的时候显示什么、出错怎么提示、按钮什么时候不能点**。
> 四态统一约定：加载用骨架或 `v-loading`；空态给文案 + 引导动作；错误给提示 + 重试；无权限跳 403 页或登录页。

### 5.1 首页 `/`

- **元素**：轮播（3 张，静态配置）、一级分类入口（图标 + 名称）、推荐商品网格（8 个，两行四列）
- **卡片字段**：主图、名称、最低价（`¥99.00` / 多 SKU 显示 `¥99.00 起`）、销量
- **空态**：「暂无推荐商品」；分类区为空时不渲染该模块，不留白块
- **操作**：点卡片进详情；点分类进列表并带上 `category_id`

### 5.2 商品列表 `/products`

- **元素**：顶部搜索框、分类筛选、价格区间（两个输入框 + 确定）、排序 Tab（综合 / 销量 / 价格升降）、商品栅格、分页器
- **状态**：筛选条件全部同步到 URL query，刷新和分享后结果一致；切换筛选重置到第 1 页
- **空态**：「没有找到相关商品，换个关键词试试」+「清空筛选」按钮
- **错误**：价格区间填反（最低 > 最高）时输入框标红并提示「最低价不能高于最高价」，不发请求
- **分页**：每页 20，选项 20/40/60；总数 0 时不显示分页器

### 5.3 商品详情 `/products/:id`

- **元素**：图集（主图 + 缩略图）、名称、价格、销量、规格选择器（按 `spec_keys` 动态生成）、数量步进器、加入购物车、库存提示
- **SKU 联动**：选中组合定位到具体 SKU，价格与库存实时变化；库存 0 的选项置灰不可选
- **按钮禁用**：未选全规格 → 禁用并提示「请选择 颜色 / 尺寸」（按缺失项动态拼）；选中 SKU 无库存 → 禁用并显示「暂时缺货」
- **限购**：单次加购 1–999，步进器到边界时按钮禁用
- **错误**：商品已下架 → 404 页「商品不存在或已下架」，给「返回列表」入口

### 5.4 购物车 `/cart`

- **元素**：全选复选框、商品行（图、名称、规格、单价、步进器、小计、删除）、失效区、底部汇总（已选件数、商品总额、运费 ¥0.00、应付总额）、去结算
- **失效项**：置灰、不可勾选、不计入总额；单独分组展示，标注「已失效」
- **角标**：导航栏购物车角标显示**商品件数**（同一 SKU 买 3 件显示 3）
- **空态**：「购物车还是空的」+「去逛逛」
- **交互**：改数量即时算小计与总额；删除需二次确认；超库存时提示「库存不足，当前仅剩 N 件」（N 取该项 `stock`），并把数量回退到修改前的值
- **按钮禁用**：未勾选任何有效商品时「去结算」禁用

### 5.5 结算页 `/checkout`

- **元素**：收货地址卡（默认地址，可切换）、商品清单（只读）、备注输入（≤200 字）、金额明细（商品总额 / 运费 / 应付）、提交订单
- **空态（无地址）**：「请先添加收货地址」+「去添加」，提交按钮禁用
- **失效拦截**：清单中有失效商品时，标红并提示「部分商品已失效，请返回购物车调整」，提交按钮禁用
- **防重复**：提交后按钮进入 loading 并禁用，直到跳转或报错

### 5.6 我的订单 `/orders`

- **元素**：状态 Tab（全部 / 待支付 / 待发货 / 待收货 / 已完成 / 已取消）、订单卡片（订单号、下单时间、首图 + 共 N 件、金额、状态、操作按钮）、分页
- **操作按钮**：`pending` → 支付 / 取消；`paid` → 无；`shipped` → 确认收货；终态 → 无
- **空态**：「还没有相关订单」+「去逛逛」

### 5.7 订单详情 `/orders/:id`

- **元素**：状态条、收货信息（快照）、商品明细（图、名、规格、单价 × 数量、小计）、金额、订单号与下单时间、状态时间线
- **时间线**：只展示已发生的节点（下单/支付成功/已发货/交易完成/已取消），按时间正序
- **注意**：收货信息是**下单时的快照**，用户后来改地址不影响这里

### 5.8 登录注册 `/login` `/register`

- **元素**：账号（邮箱或手机号）、密码；注册额外有手机号（选填）、昵称（选填）
- **校验前置**：前端先校验格式与密码强度（8–64 位、字母 + 数字），不通过不发请求
- **错误提示**：登录失败统一提示「账号或密码错误」（不区分账号是否存在）；锁定提示「尝试过于频繁，请 N 分钟后重试」
- **登录成功**：跳回 `redirect` 参数指定页面，无则回首页

### 5.9 地址管理（个人中心）

- **元素**：地址卡列表、默认标签、新增/编辑弹窗（收货人、手机号、省市区、详细地址、设为默认）、删除
- **规则**：首个地址自动默认；设新默认后原默认自动取消；删除默认后自动选 id 最小的一条
- **空态**：「还没有收货地址」+「新增地址」

### 5.10 管理端 · 商品 `/admin/products`

- **元素**：搜索框、分类筛选、状态筛选、表格（图、名称、分类、价格区间、SKU 数、总库存、销量、状态、操作）、新增按钮、分页
- **表单**：基础信息 + **动态 SKU 列表**（可增删行，每行：SKU 编码、规格键值、价格、库存、启用）
- **校验**：至少 1 个 SKU；同一商品所有 SKU 的规格键必须一致；规格组合不能重复；SKU 编码全局唯一
- **删除**：有历史订单的商品禁止删除，提示「该商品存在历史订单，请改为下架」

### 5.11 管理端 · 分类 `/admin/categories`

- **元素**：树形表格（名称、层级、排序、操作）、新增/编辑弹窗（名称、父分类、排序）
- **校验**：最多 3 级；父分类不能选自己或自己的子分类
- **删除**：有子分类或有商品（含下架）时禁止删除，提示具体原因

### 5.12 管理端 · 订单 `/admin/orders`

- **元素**：订单号搜索、状态多选、时间范围、表格（订单号、金额、状态、下单时间、操作）、发货按钮
- **发货**：仅 `paid` 可发货；点击后二次确认，成功后状态变「待收货」

### 5.13 全局交互规范

1. 提交类按钮必须有 loading + 禁用，防连点。
2. 金额一律走 `formatPrice()` 展示，禁止 JS 直接累加浮点数。
3. 401：清 token → 跳 `/login?redirect=<当前路径>`；403：提示「无权限」；404：提示「资源不存在或已删除」。
4. 删除类操作必须二次确认。
5. 表单错误定位到字段，不用全局 toast 代替字段提示。
6. 列表页的筛选、排序、页码全部体现在 URL 上。

## 6. 业务规则

> 人话版，按域分组。编号规则的完整 44 条（含技术约束）见归档版 §5。

### 6.1 账号

- 邮箱必填、唯一、不区分大小写；手机号选填但唯一，格式 `1[3-9]` 开头 11 位。
- 密码 8–64 位，必须同时含字母和数字。
- 登录支持邮箱或手机号；密码错误与账号不存在返回**同一句提示**。
- 同一账号 5 分钟内错 5 次，锁 10 分钟，锁定期内密码正确也拒绝。
- 注册成功不自动登录；token 有效期 24 小时。

### 6.2 商品与分类

- 价格和库存在 SKU 上，SPU 只管展示信息。
- 同一商品下所有 SKU 的规格键必须一致（都是「颜色 + 尺寸」，不能有的只有「颜色」）。
- 商品下架后：列表不出现、详情 404、不能加购；已在购物车里的标记失效。
- 有历史订单的商品只能下架，不能删除。
- 分类最多 3 级；不能把分类挂到自己或自己的子分类下。
- 有子分类、或有商品（含下架商品）的分类不能删除。
- 列表排序：综合与销量都按销量降序，同销量按 id 降序（保证翻页稳定）；价格排序按最低 SKU 价。
- 搜索只匹配商品名，不区分大小写，不搜 SKU 编码，不做分词。

### 6.3 购物车

- 同一 SKU 重复加购是**累加**，不新增行。
- 数量范围 1–999；加购或改数量后超过库存 → 拒绝，且原数量不变。
- 失效判定：商品下架 / SKU 被删 / 库存为 0。失效项不计入全选、不计入总价。
- 全选、单选是纯前端状态，不入库。

### 6.4 订单与支付

- 金额只由后端算，前端传的任何金额字段一律忽略。
- 下单在一个事务里完成：校验地址 → 校验购物车 → 校验商品在售 → 扣库存 → 生成订单与快照 → 清购物车。任一步失败，全部回滚。
- 多商品订单按 SKU id 升序扣减，避免死锁。
- 订单明细与收货信息是**快照**：商品后来改名改价、用户后来删地址，都不影响历史订单。
- 销量只在「支付成功」时累加，下单和完成都不加。
- 未支付 30 分钟自动取消并还库存；已发货 15 天自动确认收货。
- 状态流转只能按 §4.2 的 7 条路径走，重复操作和非法流转都拒绝。

### 6.5 地址

- 每个用户最多一个默认地址；首个地址自动默认。
- 删除默认地址后，自动把 id 最小的剩余地址设为默认；没有地址就允许为空。
- 地址是物理删除，历史订单靠快照展示。

### 6.6 权限与数据

- 带资源 id 的接口都要校验归属；**别人的资源一律返回 404，不返回 403**（403 等于告诉对方"这个 id 存在"）。
- 管理端所有接口都要求管理员身份。
- HTTP 状态码与业务码必须同时正确，不允许「HTTP 200 + 业务错误码」。
- 时间统一存 UTC；金额统一两位小数字符串。

## 7. 边界与异常（用户视角）

| 场景 | 用户看到什么 | 系统实际做了什么 |
|---|---|---|
| 库存只剩 1，多人同时下单 | 只有 1 人成功，其他人提示「库存不足」 | 条件更新扣减，库存不会变负 |
| 连点两次「提交订单」 | 只生成一个订单，第二次直接跳同一订单 | 幂等键 + 按钮禁用 |
| 重复点「支付」 | 第二次提示「当前状态不支持该操作」 | 条件更新，只生效一次 |
| 取消订单后库存 | 商品恢复可购买 | 同一事务内回滚库存，且只回滚一次 |
| 购物车里的商品下架了 | 该行灰掉，标「已失效」，不影响其他商品结算 | 不参与全选与总价 |
| 下单时商品刚好被下架 | 「商品已下架：xxx」 | 整单回滚，库存不动 |
| 用别人的订单号访问 | 「资源不存在」 | 返回 404，不暴露订单存在 |
| 搜索框输入 `' OR 1=1--` | 空结果，页面正常 | 参数化查询 + 通配符转义 |
| 上传改了后缀的脚本 | 「文件内容与图片格式不符」 | 魔数校验拦截，不落盘 |
| 登录连续输错 5 次 | 「尝试过于频繁，请 10 分钟后重试」 | 账号维度锁定，与 IP 无关 |
| 邮箱已注册 | 「该邮箱已注册」 | 唯一约束 + 前置查询 |
| 请求超时 / 服务异常 | 「服务暂不可用，请稍后重试」 | 500 不暴露堆栈，日志留 trace_id |

## 9. 验收口径

### 9.1 五条硬指标

| # | 指标 | 判定 |
|---|---|---|
| 1 | 并发不超卖 | 库存 1，50 并发下单 → 恰好 1 单成功，库存 0，明细 1 条 |
| 2 | 越权全拦 | 跨用户访问订单/购物车/地址 → 全部 404，无一条泄露 |
| 3 | 重复提交不重复扣 | 同幂等键连发 5 次 → 1 个订单，库存只扣 1 次 |
| 4 | 快照不变 | 下单后改商品名/价格/删地址 → 订单详情不变 |
| 5 | 契约自洽 | 所有接口 HTTP 2xx ⟺ 业务码 0 |

### 9.2 通过准则

交付判定采用「全部满足」制：34 条端到端验收全通过 + 83 条功能级验收点全通过 + 无 P0/P1 缺陷 + 并发与性能报告达标 + 单元测试覆盖率 ≥ 70% + CI 全绿。

> 完整验收清单（Given/When/Then 格式，可直接转 pytest 用例）见归档版 §12。

## 10. 范围外与已知限制

| 限制 | 影响 | 计划 |
|---|---|---|
| 不支持退款 | 付款后不可逆，只能走完流程 | v2.1 增加退款与逆向库存 |

| 图片存本地磁盘 | 单点，扩容需迁移 | 后续切对象存储 |
| 无软删除 | 删除即物理删除，靠拦截规则保护 | 不在规划内 |
